# BugTrack — изменения относительно модулей 1–2

Журнал всех отступлений от диаграмм (PDF модуля 2) и макетов Figma. Каждое изменение потом оформляется в Word «до → после» с причиной.

Статус: З — зафиксировано решением, Р — реализовано, Д — внесено в Word «до/после».

## Диаграммы классов (МПО/МПП)

| № | Что было | Что стало | Почему | Статус |
|---|---|---|---|---|
| К1 | Перечисления `Role`, `Priority`, `Severity`, `TriageDecision`, `Verdict`, `LinkType`, `ReleaseStatus`, `BugStatus` без значений | Значения расписаны (см. ниже) | Без значений нельзя реализовать || Р |
| К2 | `Role` не раскрыт | Руководитель проекта, Тимлид, Разработчик, Тестировщик (роли в проекте, Set<Role>) | Роли с макета «Участники» || Р |
| К3 | Администратора нет | Системная роль Администратор у Пользователя: блокировка/разблокировка учётки (поле «активен»), сброс пароля. В работу проектов не вмешивается | Нужна поддержка системы || Р |
| К4 | У Пользователя метод `войти(пароль)`, но нет поля пароля | Добавлено `парольХеш: String` | Без пароля вход невозможен || Р |
| К5 | Регистрации нет | Саморегистрация (имя, email, пароль); создатель проекта становится Руководителем | Иначе неоткуда взять пользователей || Р |
| К6 | `BugStatus` только из активностей | Новый, Нужно уточнение, Назначен, В работе, На проверке, Закрыт, Отклонён, Дубликат | «Запросить уточнение у автора» на макете триажа не имело статуса || Р |
| К7 | `TriageDecision` без значений | Принять, Запросить уточнение, Дубликат, Отклонить | Совпадает с кнопками макета «Триаж» || Р |
| К8 | `Priority`, `Severity` | Приоритет: Высокий/Средний/Низкий. Серьёзность: Критическая/Значительная/Незначительная | Значения из макетов и отчёта || Р |
| К9 | `LinkType` | Дубликат, Связан, Регрессия, Блокирует | Дубликат/регрессия есть на макетах, «Блокирует» добавлен по решению команды || Р |
| К10 | `ReleaseStatus` | Планируется, Выпущен, Отменён | «Отменён» — чтобы не удалять ошибочные релизы || Р |
| К11 | `Verdict` | Подтверждено, Возвращено | Два исхода на диаграмме проверки || Р |
| К12 | Нет авторов у Комментария, Записи истории, Попытки исправления, Результата проверки, Бага | Связь «автор» (Участник проекта) у каждого | Иначе не показать «Анна · сегодня» и не проверить, что проверяющий ≠ разработчик || Р |
| К13 | В МПП методы принимают `Membership`, такого класса нет | `Membership` = «Участник проекта» | Несовпадение имени || Р |
| К14 | `ссылкаНаИзменение: String` (одна) | Список ссылок на коммиты/MR + `причинаБезСсылки` | ТЗ м.1: «ссылки на коммиты/MR»; макет «Если ссылки нет» || Р |
| К15 | У Проекта нет описания и репозитория | Добавлены `описание`, `репозиторий` | Есть на макетах «Проекты» и «Участники и настройки» || Р |
| К16 | Изменение дедлайна проекта без причины | Причина пишется в Запись истории | Макет «Причина изменения» || Р |
| К17 | У Решения триажа нет причины приоритета | Поле `причина` используется и как причина приоритета; добавлен назначенный срок/релиз через Баг | Макет «Причина приоритета» || Р |
| К18 | У Релиза нет описания | Добавлено `описание` | Макет «Релизы» || Р |
| К19 | Уведомлений нет в модели | Новый класс Уведомление (получатель, текст, ссылка на баг/релиз, прочитано, дата) + письмо на почту | На диаграммах есть «Сообщить…», но некому хранить | З |
| К20 | Нет поля версии для конкурентного редактирования | `version` у Бага (оптимистичная блокировка) | Макет «Если карточка изменилась — обновите» || Р |
| К21 | Метод `Баг.закрыть(релиз)` пересекается с `РезультатПроверки.подтвердить(релиз)` | Подтверждение создаёт результат, баг закрывается внутри того же действия | Одно действие — одна точка входа || Р |
| К22 | «Записать препятствие» | Сохраняется как Комментарий с пометкой «препятствие», статус «На проверке» не меняется | Так на диаграмме активности; отмечаем явно | Р |
| К23 | Связь «баг исправлен в релизе» не указана | У Результата проверки поле `релизИсправления` | Активность «Сохранить подтверждение и связать баг с релизом» | Р |
| К24 | Неясно, откуда берётся номер бага | У Проекта счётчик `последнийНомерБага`, номер = КЛЮЧ-N (BT-142) | Номер бага нужен по макетам и диаграммам | Р |
| К25 | История есть только у Бага | Новый класс Запись истории проекта (действие, было/стало, причина) | Изменение дедлайна проекта с причиной (К16) | Р |
| К26 | Вложение не связано ни с кем, кроме бага | Вложение принадлежит Багу и может относиться к Комментарию или Результату проверки | «Прикрепить файл» к комментарию; «Свидетельства» при проверке | Р |
| К27 | Нет дат создания/изменения у Бага, Комментария, Попытки | Добавлены `создан`, `изменён` | Сортировка, «Анна · сегодня», отчёт по периоду | Р |
| К28 | Неясно, кто может сменить исполнителя | Взять баг может только разработчик; если исполнитель уже назначен — только он | Активность «Закрепить исполнителя» | Р |

## Компоненты

|---|---|---|---|---|

## Правила, которых не было

| № | Правило | Статус |
|---|---|---|
| П1 | Права: баг создаёт любой участник; триаж — Тимлид (и Руководитель); исправление — Разработчик; проверка — Тестировщик, не автор исправления; релизы — Руководитель и Тимлид; участники и настройки — Руководитель || Р |
| П2 | Вложения: до 10 МБ, png/jpg/gif/txt/log/pdf/zip, до 5 файлов за раз | З |
| П3 | Уведомления (в системе + email): новый баг → тимлиду; назначение/возврат → разработчику; на проверку → тестировщику; релиз выпущен → команде | З |
| П4 | Отчёт выгружается в Excel (.xlsx) | З |
